# Dify 前端项目结构说明

> 本文档用于说明 Dify Web 前端项目的目录结构和页面组织方式

## 项目概述

这是 Dify 的前端 Web 应用，基于 **Next.js 15** 和 **React 19** 构建，使用 TypeScript 开发。

**技术栈**:
- React 19.1.1
- Next.js 15.5.6 (App Router)
- TypeScript 5.9.3
- Tailwind CSS 3.4.18
- Zustand (状态管理)
- TanStack Query (数据获取)

## 🎯 页面文件位置：/app 目录

### Next.js App Router 说明

本项目使用 **Next.js 15 的 App Router**（而非旧版的 Pages Router）。

**关键概念**:
- `page.tsx` = 页面组件
- `layout.tsx` = 布局组件
- `loading.tsx` = 加载状态
- `error.tsx` = 错误边界
- `route.ts` = API 路由
- `(groupName)` = 路由分组（不影响 URL）
- `[param]` = 动态路由参数

## 📦 主要功能模块

### 1. 应用管理 (Apps)
- **页面**: `app/(commonLayout)/apps`
- **组件**: `app/components/app/`, `app/components/apps/`
- **API**: `service/apps.ts`
- **功能**: 创建、编辑、删除、复制应用；应用类型选择

### 2. 数据集管理 (Datasets)
- **页面**: `app/(commonLayout)/datasets`
- **组件**: `app/components/datasets/`
- **API**: `service/datasets.ts`, `service/knowledge/`
- **功能**: 知识库管理、文档上传、检索增强生成 (RAG)

### 3. 工作流编辑器 (Workflow)
- **页面**:
  - 内部: `app/(commonLayout)/workflow`
  - 公开: `app/(shareLayout)/workflow/[token]`
- **组件**: `app/components/workflow/` （复杂度高）
- **功能**: 可视化工作流编辑、节点管理、流程设计

### 4. 工具和插件 (Tools & Plugins)
- **页面**: `app/(commonLayout)/tools`, `app/(commonLayout)/plugins`
- **组件**: `app/components/tools/`, `app/components/plugins/`
- **API**: `service/tools.ts`, `service/plugins.ts`
- **功能**: 工具市场、自定义工具、MCP 支持、插件管理

### 5. 聊天分享 (Chat & Share)
- **页面**: `app/(shareLayout)/chat/[token]`, `app/(shareLayout)/chatbot/[token]`
- **组件**: `app/components/share/`
- **API**: `service/share.ts`
- **功能**: 公开聊天、嵌入式聊天机器人

### 6. 账户和认证 (Account & Auth)
- **页面**: `app/signup`, `app/signin`, `app/account`
- **组件**: `app/components/signin/`
- **功能**: 用户注册、登录、OAuth 认证、密码重置

## 📚 重要开发规范

### 1. 国际化规范
✅ 必须使用 `i18n` 系统，禁止硬编码文本
```typescript
import { useTranslation } from 'react-i18next'

const { t } = useTranslation()
const text = t('common.save')  // ✅ 正确
const text = '保存'             // ❌ 错误
```

### 2. API 调用规范
✅ 所有 API 调用必须通过 `service/` 层
```typescript
import { fetchAppList } from '@/service/apps'  // ✅ 正确

// ❌ 错误：不要直接在组件中调用 fetch
fetch('/api/apps')
```

### 3. 类型安全规范
✅ 使用严格的 TypeScript 类型，避免 `any`
```typescript
interface User {  // ✅ 正确
  id: string
  name: string
}

const user: any = {}  // ❌ 错误
```

### 4. 组件规范
✅ 优先使用 `app/components/base/` 中的基础组件
✅ 保持组件独立和可复用
✅ 使用 TypeScript 定义 Props 类型
